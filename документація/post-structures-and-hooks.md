# Дослідження: структури постів/рілсів і хуки (#247)

> Методологічний документ (БЕЗ реалізації). Основа для конструктора постів (#248)
> і для скорингу елементів. Термінологія узгоджена з атомарною моделлю (Ф3.0/A):
> юніт = `PostGroup`, елементи-атоми = поля `hookA/hookB/hookSelected/cta/structureId/
> evidenceType/caseId/skeleton/scores/intent`.

## 1. Навіщо це

Пост — не суцільний текст, а **набір структурних елементів**, кожен з яких виконує
свою роботу (зупинити скрол, утримати, довести цінність, спонукати до дії). Якщо
розкласти пости на елементи й міряти результат, можна:
- давати боту/автору **конструктор** (збери пост з перевірених блоків),
- нараховувати кожному елементу **бали ефективності** й підказувати найкращі,
- уникати повторів і «цементування» одного шаблону (звʼязок з #295 anti-repeat, #306 experiment).

## 2. Анатомія поста (універсальний каркас)

Будь-який пост = послідовність **слотів**. Не всі обовʼязкові; порядок залежить від формату.

| Слот | Робота | Приклади реалізації |
|------|--------|---------------------|
| **Hook** (гачок) | зупинити скрол за 1-2 сек | питання, провокація, цифра, обіцянка, біль |
| **Context/Setup** | дати рамку, «це про тебе» | коротка ситуація, кому це болить |
| **Value/Body** | основна цінність | кроки, інсайт, історія, розбір |
| **Evidence** | довести (тип: `evidenceType`) | кейс із цифрами, скрін, соц.доказ, особистий досвід |
| **Turn/Insight** | несподіваний поворот/висновок | «а насправді…», переосмислення |
| **CTA** (`cta`) | спонукати до дії | питання в коментарі, лід-магніт, збережи, напиши |

**Правило:** сильний пост має мінімум Hook + Value + (Evidence або Turn) + CTA.

## 3. Структури (скелети) за форматами

`structureId` вказує на один із канонічних скелетів. Пропоновані:

### 3.1 Текстові (Threads / LinkedIn / IG-текст-пост)
- **AIDA-lite:** Hook(біль) → Value(рішення) → Evidence(кейс) → CTA.
- **PAS:** Problem → Agitate(підсилити біль) → Solution → CTA.
- **Кейс:** Hook(результат-цифра) → Setup(було) → Value(що зробили) → Evidence(стало) → CTA.
- **Інсайт/думка вголос:** Hook(теза) → Context → Turn(несподіваний кут) → CTA(обговорення).
- **Лістикл:** Hook(«N способів…») → 3-5 пунктів (кожен = мікро-Value) → CTA(збережи).
- **Провокація:** Hook(непопулярна думка) → Аргумент → Baланс/нюанс → CTA(згоден?).

### 3.2 Карусель (IG-carousel)
- Слайд 1 = Hook (обкладинка-обіцянка). Слайди 2..N-1 = по одному кроку Value.
  Слайд N = Evidence+CTA. Кожен слайд = окремий `PostItem`, але скелет — на рівні юніта.

### 3.3 Reels / TikTok / короткі відео
- **Перші 3 секунди = все.** Hook візуальний + вербальний одночасно.
- Скелети: **Hook(3с) → Швидка обіцянка → 3 биті цінності → CTA**; або **Проблема → демо-рішення → результат**.
- Специфіка: ретеншн-крива, патерн-інтеррапти (зміна кадру/тексту кожні 2-3с), субтитри завжди.

### 3.4 Stories
- Мікроформат: Hook-стікер (питання/опитування) → 1 думка → свайп/CTA. Скелети: анонс рілсу,
  закулісся, питання-опитування, лід-магніт.

## 4. Бібліотека хуків

Хук зберігається у двох варіантах (`hookA`/`hookB`) для A/B, обраний — `hookSelected`.
Типи хуків (кожен придатний для скорингу):

| Тип хука | Механіка | Коли працює | Приклад-шаблон |
|----------|----------|-------------|----------------|
| **Питання** | цікавість/само-ідентифікація | широка аудиторія | «Чому {X} не працює, хоча ти робиш все правильно?» |
| **Провокація** | конфлікт/незгода | активна аудиторія | «Непопулярна думка: {теза}» |
| **Цифра/статистика** | конкретика | B2B, експертний | «{N}% {кого} втрачають {що} через {причину}» |
| **Обіцянка/результат** | вигода | продажні пости | «Як {досягти X} за {термін} без {болю}» |
| **Біль (дзеркало)** | впізнавання | вузька ЦА | «Ти відкриваєш {інструмент} і знову {біль}…» |
| **Історія-відкриття** | наратив | сторітелінг | «Клієнт прийшов з {проблема}. Через місяць — {результат}.» |
| **Контрінтуїція** | розрив шаблону | залучення | «Роби навпаки: {несподіване}» |
| **Лістикл-анонс** | збереження | корисний контент | «{N} способів {результат}, які ти ще не пробував» |

**Принципи хука:** конкретика > абстракція; «ти/тобі» > «ми/наш»; один хук = одна ідея;
перші 5-7 слів вирішують.

## 5. Методологія вимірювання ефективності (для скорингу #248/#305)

Мета — нараховувати **бали ефективності** кожному елементу (хук, структура, evidenceType, CTA),
щоб бот/автор обирали кращі.

### 5.1 Сигнали (звідки бали)
1. **Ручні реакції** (`analytics/manual` → `scores` на юніті): лайки×1, коменти×2,
   перегляди сторіз×1, підписки×5, продажі×10 (ваги конфігуровані).
2. **Кліки по лід-магніту** (`link-stats`) — прокси конверсії.
3. **Аналіз сторінок** (майбутнє): парсинг метрик соцмереж → нормалізовані показники.

### 5.2 Атрибуція елементу
- Бал юніта розкладається на його елементи; накопичується у **WinningPattern**
  (тип елемента → значення → середній бал, к-ть спостережень) — вже є (#306).
- Формула балу елемента: `score = zscore(середній результат юнітів з цим елементом)`,
  з мінімальним порогом спостережень (напр. ≥5), інакше «недостатньо даних».

### 5.3 Захист від хибних висновків
- **Мін. вибірка** перед висновком; **anti-repeat** (#295) щоб не цементувати;
  **experiment** (#306, ≤3 активних) для контрольованої перевірки гіпотез;
  сегментація за форматом/мережею (хук для Reels ≠ хук для LinkedIn).

### 5.4 План дослідження (без реалізації — це і є суть #247)
1. Зібрати корпус опублікованих постів з розміткою елементів (структура, тип хука, evidenceType, CTA).
2. Підтягнути результати (ручні реакції + кліки).
3. Порахувати середній результат по кожному значенню елемента (з порогом вибірки).
4. Побудувати рейтинг елементів **у розрізі формату й мережі**.
5. Перевірити топ-гіпотези через `experiment` (A/B хуків `hookA`/`hookB`).
6. Оновлювати `WinningPattern` періодично; показувати автору/боту як підказки в конструкторі.

## 6. Що з цього реалізує #248 (конструктор)

- UI у картці поста: обрати **тему(intent) / категорію / хук(тип+текст A/B) / структуру / evidenceType / CTA**.
- Біля кожного варіанту — **бал ефективності** з `WinningPattern` (або «мало даних»).
- Збереження у відповідні поля `PostGroup` (атомарна модель).
- Кнопка «зібрати скелет» → генерація за обраною структурою (звʼязок з двофазною генерацією).

## 7. Відкриті питання
- Джерело метрик сторінок: ручний ввід vs інтеграції API соцмереж (потребує токенів).
- Гранулярність структур: фіксований набір скелетів vs вільна композиція слотів.
- Персоналізація рейтингів під нішу клієнта (мультитенант, звʼязок з #258).
