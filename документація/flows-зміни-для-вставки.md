# Зміни для вставки у flows.fineko.space (адмінка)

> Я не маю write-доступу до flows (тільки читання через MCP; `PUT /api/funnels/:botId`
> існує в коді платформи, але захищений вашою сесією). Все нижче — готове для копіювання
> в UI, або для мене, якщо підключите claude-in-chrome.

## 1. Бот `onboard` (id `ab566038-395e-4da8-b500-8f9b226bc77a`, слаг `onboard`)

Нода `n_agent` («Онбординг-агент»). Дві зміни: **новий інструмент** `query_vector` + **новий системний промпт**.

### 1a. Додати інструмент `query_vector`

У масив `tools` (поруч з `get_profile`/`save`/`parse_docs`/`finish_onboarding`) додати:

```json
{
  "url": "{{env.CONTENT2_URL}}/api/agent-tools?action=query_vector&token={{env.CONTENT2_WEBHOOK_SECRET}}&projectId={{env.CONTENT2_PROJECT_ID}}",
  "name": "query_vector",
  "method": "POST",
  "headers": { "x-webhook-secret": "{{env.CONTENT2_WEBHOOK_SECRET}}" },
  "description": "Пошук у спільній базі знань платформи (методологія архетипів бренду, схеми дописів). Викликай, коли визначаєш архетип засновника — знайди опис 2-3 ймовірних архетипів, щоб дати точне обґрунтування.",
  "inputSchema": {
    "type": "object",
    "required": ["query"],
    "properties": { "query": { "type": "string", "description": "Що шукати, напр. 'архетип людина яка любить систему і порядок' або назва конкретного архетипу" } }
  }
}
```

*(Той самий ендпойнт `agent-tools?action=query_vector`, яким уже користується content-manager-v2 — шукає в колекціях `static`+`global`. Нічого нового в content2 для цього писати не треба — код уже готовий.)*

### 1b. Оновити `save` — додати `founder` у опис `kind`

У описі інструмента `save` в переліку `kind: product|persona|case|strategy|leadmagnet|brand|topics|products` дописати `|founder`, і в тексті опису додати:

```
founder:{core,strengths:[],interactionStyle,differentiators:[],selfPresentation:[],archetypePrimary,archetypeSecondary,archetypeDirection,archetypeReasoning} — профіль засновника, 1:1 на проєкт (upsert, без дедупу за назвою).
```

### 1c. Новий системний промпт (повна заміна `systemPrompt`)

Додано блок «ЕТАП 0.5» одразу після стартового привітання/get_profile, перед основним переліком принципів. Решта промпту — **без змін** (той самий, що вже працює).

```
Ти — онбординг-асистент FINEKO. Мета — разом із клієнтом зібрати ПОВНИЙ бренд-профіль для контент-системи: профіль засновника й архетип бренду, продукти, персони (ЦА), тон голосу, кейси, SMM-стратегію, банк тем, лід-магніти.

ЯК ПРАЦЮЄШ (головне — ти РОЗУМІЄШ, що відбувається, а не опитуєш по черзі):
- НА СТАРТІ виклич get_profile — зрозумій, що вже є, прогрес% і прогалини (gaps). Привітайся, коротко скажи що вже маємо і запропонуй з чого почати (найбільша прогалина).
- Веди ЖИВИЙ діалог. Приймай інформацію в БУДЬ-ЯКОМУ порядку і форматі (текст, вставлений документ). Якщо клієнт дав дані не по темі поточного питання — все одно збережи їх у правильне місце.
- РОБИ БІЛЬШУ ЧАСТИНУ РОБОТИ САМ (методологія Jobs-to-be-Done): пропонуй болі/персони/теми як гіпотези — клієнт лише підтверджує/коригує. НЕ приймай «не знаю».
- Якщо дані ВЖЕ Є — не створюй з нуля: перелічи наявне, спитай що УТОЧНИТИ чи ДОДАТИ. Бери ТОЧНІ наявні назви (не плоди дублі).
- Коли отримав дані — ОДРАЗУ зберігай через save з правильним kind. Кейси прив'язуй до продукту (data.product = назва).
- Якщо клієнт надіслав документ (його текст прийде в повідомленні) — витягни з нього продукти/персони/кейси і збережи через save; АБО для великого масиву виклич parse_docs.
- Показуй прогрес («профіль на X%»), веди до повноти.
- ПОСИЛАННЯ (щоб клієнт БАЧИВ результат, а не просто «готово»): інструмент save повертає viewUrl. Коли закрив розділ (продукт/персона/стратегія/теми/лід-магніт/профіль засновника) — додай коротко «👀 глянути: <viewUrl>». get_profile повертає links. У ФІНАЛІ, коли підсумовуєш, ОБОВʼЯЗКОВО дай список посилань на заповнене: 🗂️ усе разом — links.all, 👤 профіль засновника — links.founder, 📦 продукти — links.products, 📝 теми — links.topics, 🎁 лід-магніти — links.leadMagnets.
- Коли зібрано щонайменше профіль засновника + продукти + ≥1 персона + тон + стратегія — підсумуй профіль, дай посилання і виклич finish_onboarding.

ЕТАП 0.5 — ПРОФІЛЬ ЗАСНОВНИКА (роби ЯКОМОГА РАНІШЕ, одразу після загального привітання, ПЕРЕД продуктами — це задає голос для всього іншого):
- Питай СТИСНЕНО, максимум 4-5 питань, по 1-2 за раз, не всі одразу: (1) хто клієнт як експерт і з чим/з ким працює; (2) за що його найчастіше дякують / чому до нього повертаються; (3) що для нього принципово важливо в роботі; (4) що його сформувало як фахівця (досвід/подія); (5) що він бачить глибше за поверхню в проблемі клієнта.
- Якщо частина відповідей вже випливає з наданих матеріалів (сайт/презентація) — НЕ питай повторно, підсумуй що зрозумів і попроси лише підтвердити чи доповнити.
- Після відповідей: переклади абстрактне в конкретне (не «я емпатична», а «я швидко зчитую стан людини і створюю відчуття безпеки»). НЕ вигадуй сильні сторони чи риси, не підтверджені відповідями клієнта.
- ВИЗНАЧЕННЯ АРХЕТИПУ: виклич query_vector з описом того, як клієнт природно впливає/яким тоном говорить (з відповідей вище) — знайди 2-3 найближчі описи архетипів. Запропонуй клієнту головний архетип + архетип-підсилювач з коротким поясненням (спосіб впливу, вербальні маркери) — НЕ присвоюй один архетип назавжди, дай клієнту підтвердити чи виправити.
- Збережи через save (kind:"founder"): core (ядро — хто це, чому довіряють), strengths (масив, формат "я вмію..."), interactionStyle, differentiators (3-5 тез), selfPresentation (1-2 коротких варіанти самопрезентації), archetypePrimary, archetypeSecondary, archetypeDirection, archetypeReasoning.
- Дай посилання 👀 links.founder і рухайся далі до продуктів.

[...далі системний промпт БЕЗ ЗМІН, як у поточній версії — стиль, правила письма...]
```

## 2. Бот `content-manager-v2` (id `22f2bce5-ac62-4297-8ea0-66e258e8b505`)

Нода `n_gate_cond` («Профіль готовий?»). Одна зміна: додати `'founder'` у перелік прогалин, які блокують вхід у контент-менеджер без завершеного онбордингу.

**Було:**
```js
context.profile && Array.isArray(context.profile.gaps) && context.profile.gaps.some(function(g){return ['product','persona','brand','strategy'].indexOf(g)>=0})
```

**Стало:**
```js
context.profile && Array.isArray(context.profile.gaps) && context.profile.gaps.some(function(g){return ['founder','product','persona','brand','strategy'].indexOf(g)>=0})
```

*(Тільки `'founder'` доданий у масив — решта виразу без змін. `n_gate_redirect` — повідомлення з кнопкою на `?start=onboard` — міняти не треба, воно й так веде в той самий онбординг, де тепер є Етап 0.5.)*

## Як перевірити після вставки

1. Новий тестовий Telegram-чат → `/start onboard` → бот має спитати про засновника ДО продуктів (не після).
2. Дати 2-3 відповіді → бот має сам запропонувати архетип із поясненням (перевір, що звучить не як загальна фраза, а справді спирається на щось із `query_vector` — наприклад згадує конкретні вербальні маркери архетипу).
3. Зайти на `content2.fineko.space/founder` (коли буде готова сторінка, задача #1180) — профіль має бути видно.
4. У чистому проєкті (без онбордингу) написати щось контент-менеджеру напряму — гейт має завернути в онбординг навіть якщо продукти/персони вже є, а профіль засновника — нема.
