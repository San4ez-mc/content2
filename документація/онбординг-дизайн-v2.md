# Онбординг v2 — редизайн (Агент A)

> Джерело: ТЗ (doc1 §5.A + §3-4) + правки Олександра (2026-07-31).
> Легенда: ✅ є · 🟡 частково · ❌ нема (план). Статуси — станом на 2026-07-31.

## Головні принципи (нове)

1. **ШІ робить більшу частину роботи, не людина.** Люди часто не знають своїх болів,
   персон, тем. Бот не питає «які болі?» — він **пропонує гіпотези за методологією**
   (JTBD, pain-mapping), а людина лише **підтверджує/коригує/додає**. Патерн
   «ШІ пропонує → людина курує» повторюється на кожному етапі (болі, персони, теми,
   лід-магніти). ❌ зараз (боти пасивно приймають «не знаю»).

2. **Спільна пам'ять онбордингу — питання не повторюються.** Усі етапи читають/пишуть
   один профіль компанії в content2. Перед будь-яким питанням бот **завантажує вже
   відоме і питає лише дірки** (це і є Confidence Check). Сказане одному боту —
   інший підхоплює. ❌ зараз (кожна воронка питає з нуля, дублює companyName).

3. **Приймання документів.** На вході можна закинути сайт/презентації/брендбук/будь-що
   → ШІ читає, витягує факти, дедуплікує проти відомого, наперед заповнює профіль,
   показує «ось що я вже зрозумів». ❌ зараз.

4. **Все дописується, не замінюється.** Повторний онбординг доповнює сторінки
   (Продукти/Персони/Теми…), а не перетирає. Дедуп за назвою (той самий → апдейт). 🟡

## Архітектура ботів (можна перебудовувати кількість/порядок)

Замість 3 жорстких воронок — **керована послідовність зі спільним станом**. Кожен етап
= окрема воронка flows, але всі читають/пишуть один `OnboardingProfile` (проєкт content2).

### Етап 0 — Прийом матеріалів ❌
- **Людина:** «Закинь усе, що є — сайт, презентації, брендбук, старі пости». Або «нічого нема».
- **ШІ:** парсить документи (текст + LLM-витяг) → наперед заповнює профіль → рапортує
  «зрозумів: компанія X, продукт Y, тон Z; чого бракує — питатиму».
- **Зберігається:** сирі файли → `MediaItem` (folder `onboarding-docs`); витягнуті факти → у
  відповідні моделі; знижує кількість подальших питань.

### Етап 1 — Компанія + Продукти ✅→🟡
- **Людина відповідає:** назва компанії; що продаєте (коротко); ціни. Болі — **не питаємо
  в лоб**.
- **ШІ робить:** з опису+матеріалів **пропонує болі/трансформацію/переваги за методологією**
  → людина підтверджує/править. Формулює `priority` продуктів.
- **Створюється / сторінка:** `Product` {name, description, **pains, transformation,
  benefits (окремі поля — розширити модель)**, price, audience, priority} → **сторінка
  «Продукти» (дописується, дедуп за назвою)** + вектор Static.
- **Дірки для закриття:** розділити болі/трансформацію/переваги в окремі поля; методологія
  проб-гіпотез.

### Етап 2 — Кейси (рано — дають багато інформації) ❌
- **Людина:** «Розкажи 1-3 історії клієнтів: хто, з чим прийшов, що вийшло (цифри)».
- **ШІ робить:** структурує у `Case` {ніша, проблема, рішення, метрики, **дозволені
  формулювання**}; **з кейсів зворотно виводить болі/персони/продукти** і доповнює профіль
  (спільна пам'ять).
- **Створюється:** `Case` (+ `case_id`) → вектор Static. **Критично** для case-integrity/anti-repeat.

### Етап 3 — Аудиторія + Тон ✅→🟡
- **Людина:** підтверджує/коригує.
- **ШІ робить:** **сам пропонує персони** (з продуктів+кейсів+матеріалів): болі, мрії,
  **тригери, заперечення, мова** → людина курує. **Кілька персон.** ToV — ШІ **драфтить**
  із матеріалів, людина править.
- **Створюється:** `Persona` (розширити: triggers, objections, language) + `KnowledgeEntry(brand)` → Static.
- **Дірки для закриття:** triggers/objections/language; кілька персон; ШІ-драфт замість опитника.

### Етап 4 — SMM-стратегія + Банк тем ✅→🟡
- **Людина:** дає напрямок; **курує теми** (лишити/додати/прибрати).
- **ШІ робить:** пропонує контент-стовпи + **~50 тем** (з усього зібраного).
- **Створюється:** `SmmStrategy` + **~50 `ContentTopic` (status=idea) на сторінку «Теми»**;
  людина курує там. **Стратегія = документ, що качається (.docx ✅ `section=strategy`) і
  редагується** (потрібна edit-сторінка стратегії 🟡).

### Етап 5 — Лід-магніти (фінал) ❌
- **ШІ робить:** пропонує лід-магніти під кожен продукт (з болів+продуктів+воронок) → людина курує.
- **Створюється:** `LeadMagnet` (→product, →funnel, deep-link) → Static.

## Окремий блок (обговорити пізніше) — Platform-профілі / конструктор постів
Не в онбординг-опитнику. Потрібен **конструктор**: при створенні поста система бере
(1) як писати під конкретну мережу → (2) структуру поста саме для цієї мережі →
(3) хук, якщо структура містить хук, і т.д. Є готові документи по соцмережах — заведемо в
**Global** індекс + окремі сутності `PlatformProfile`/`PostStructure`. Проєктуємо окремо.

## Що поміняти в даних/коді (план реалізації)
- Спільний профіль + «читати відоме, питати дірки» (Confidence Check) — новий read-ендпойнт
  content2 + логіка в кожній воронці.
- Розширити `Product` (pains/transformation/benefits/priority), `Persona` (triggers/objections/language).
- Приймання документів: `MediaItem folder=onboarding-docs` + парсер + LLM-витяг.
- Дедуп-запис (append, не replace) у `onboarding-save`.
- Теми: воронка пише ~50 `ContentTopic(status=idea)`; курація на `/topics`.
- Стратегія: edit-сторінка + .docx (✅ download є).
- Фікс таргетингу проєкту (не плодити дублі).
- Методологія болів/персон/тем у системних промптах Claude-нод.
